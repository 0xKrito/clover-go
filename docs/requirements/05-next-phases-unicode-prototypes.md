## 2. 原型二：文件夹瑞士军刀微工具（收纳与一键解散）

### 2.1 弹窗 A：“将所选项目收进新文件夹”
选中 1 个或多个文件/文件夹，右键选择“收进新文件夹”，弹出轻量命名确认框：

```text
┌─────────────────────────────────────────────────────────────┐
│ 📁 收进新文件夹                                         [✕] │
├─────────────────────────────────────────────────────────────┤
│ 即将把已选中的 4 个项目移动至新创建的文件夹中：              │
│                                                             │
│ 新文件夹名称：                                              │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ 2026-Q4-设计素材_归档                                   │ │
│ └─────────────────────────────────────────────────────────┘ │
│                                                             │
│ 包含项目：                                                  │
│ • logo_draft1.png (2.4 MB)                                  │
│ • logo_draft2.png (3.1 MB)                                  │
│ • fonts.bundle (12.8 MB)                                    │
│ • readme.txt (1.2 KB)                                       │
│                                                             │
│ [✓] 创建后直接定位并展开该文件夹                             │
├─────────────────────────────────────────────────────────────┤
│                                          [ 取消 ]  [ 确定 ] │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 弹窗 B：“解散文件夹（Flatten）至上一级”
对于已归档或嵌套过深的目录，右键“解散文件夹”，将其子项目全部上提一层并清理空文件夹：

```text
┌─────────────────────────────────────────────────────────────┐
│ ⚠️ 解散文件夹确认                                        [✕] │
├─────────────────────────────────────────────────────────────┤
│ 确定要解散文件夹 “04_Archive_Lab” 吗？                       │
│                                                             │
│ 影响范围：                                                  │
│ 1. 文件夹内的 6 个项目将被移动至上一级目录：                │
│    目标目录: /Users/developer/Desktop/Projects/             │
│ 2. 原空文件夹 “04_Archive_Lab” 将被自动清理                 │
│                                                             │
│ 冲突检测与安全策略：                                        │
│ • 同名文件处理策略:                                         │
│   (●) 保留两者（同名文件自动追加 “_copy” 后缀）             │
│   ( ) 仅保留较新的文件                                      │
│ • 撤销保障: ⌘Z 支持在 60 秒内完整恢复该文件夹结构            │
├─────────────────────────────────────────────────────────────┤
│                                          [ 取消 ]  [ 解散 ] │
└─────────────────────────────────────────────────────────────┘
```

## 6. 四种极限交互态矩阵定义 (Edge-case States)

为保证在极端或异常物理边界下系统的健壮性，各模块必须严格实现以下四种极限态：

| 交互状态 | 典型场景 | 视觉表现与反馈定义 | 恢复与降级动作 |
| :--- | :--- | :--- | :--- |
| **1. 空数据态 (Empty State)** | • 虚拟包内为空目录<br>• 搜索/过滤无匹配项<br>• 书签栏无任何书签 | • 居中显示浅灰线描图标 + 友好引导文字<br>• 如：“此压缩包内没有文件”、“书签栏：在文件夹上右键可添加至此” | 提供“返回上一级”或“清除搜索关键词”的一键重置按钮。 |
| **2. 加载等待态 (Loading State)** | • 解析 2GB+ 超大 `.zip` 压缩目录<br>• 批量加水印 100+ 张 4K 原图 | • 避免界面假死（严格在后台异步 Goroutine 执行）<br>• 列表显示占位骨架屏（Skeleton）或旋转加载圈<br>• 状态栏显示进度条：`正在解析包内目录结构... (45%)` | 提供右上角 `[ 取消 ]` 按钮，用户可主动中断解析。 |
| **3. 异常报错态 (Error State)** | • 压缩包已损坏或 CRC 校验失败<br>• ZIP 带有密码保护（AES 加密）<br>• 目标目录无写入权限 | • 内联警示条，黄色/红色高亮<br>• 若遇加密 Zip，弹出原生密码输入框：`🔑 请输入压缩包解密密码`<br>• 密码错误时高亮晃动输入框，允许重复尝试 | 无法解析时安全回退，不崩溃退栈，保留在原目录。 |
| **4. 极端数据态 (Extreme State)** | • 压缩包内展开超过 10,000 个文件<br>• 超长文件名（>200 字符）<br>• 嵌套深度超过 20 层的深层目录 | • 文件列表强制采用虚拟滚动（`ui.List` 仅渲染可视区 30 行），CPU 零尖峰<br>• 超长文本中间截断（如 `very_long_project_name..._final.zip`），鼠标悬停显示完整 Tooltip | 禁用一次性内存分配，按需流式读取 Zip Central Directory。 |
